## Save recovery and retained-progress update

Added explicit damaged/incompatible-save recovery with validated previous-save selection and confirmed restart. Original stored records are copied atomically to a separate recovery archive before either choice; the most recent original can be exported before and after recovery. Recovery rechecks the complete inspected row inside the transaction and rejects concurrent changes. Stored revisions must agree with validated command replay. A malformed current save is never silently overwritten or presented as a valid backup.

The controller tracks durable revision separately from current volatile progress. Storage retry commits the retained state directly, including actions made after explicitly choosing temporary mode. Failed writes do not repeat actions or charge time twice. Temporary mode identifies its last committed revision, provides export, and does not erase the durable case when restarting a temporary session. Write conflicts offer export and an explicit discard/reload choice. Waiting Web Lock tabs refresh the committed case when ownership transfers.

The version-1 portable envelope and ruleset are unchanged. Raw recovery exports preserve stored records for inspection and are not portable import files. Full snapshot/trailing-log restoration, committed receipt promotion, supported migrations, fallback leases, real storage eviction and abrupt browser termination remain open. ## Snapshot save format and committed receipt update

Format 2 now stores a pinned M01 manifest (world, fixture hash and engine compatibility ID), run ID, complete canonical command log, current revision, last committed revision, full engine snapshot at an explicit command boundary, snapshot/final gameplay-state hashes and producer/checksum metadata. The snapshot includes immutable acquisitions, internal facts/cache, draft, pending checks with absolute due ticks, original receipts, history and the frozen debrief. Presentation still receives only the permitted player projection.

The reader checks size, nesting, unsafe keys, versions, schema bounds, content compatibility, envelope checksum and command boundaries. It independently audits the snapshot against the command prefix, then restores the validated snapshot and executes only trailing commands. It checks the final gameplay hash; commands already represented in the snapshot are not applied again. Validation currently reconstructs the prefix and therefore is not a constant-time restore optimization. Storage acknowledgements are excluded from gameplay hashes and cannot alter scores, source facts or timing.

Transactions write an acknowledged clone and return it only on successful completion. The controller exposes that returned state; failure leaves the prepared in-memory action and its receipt memory-only. Original committed receipts survive resume and idempotent duplicate commands. Normal exports remain deterministic, including after media preference changes.

Format-1 imports remain supported. Reading an old database row does not change its bytes. Its next successful commit writes format 2 and retains the old envelope as the previous backup; failed upgrades leave the old row untouched. Future unsupported content/format versions take the existing original-export and explicit recovery/restart path. Older builds cannot import new format-2 files.
